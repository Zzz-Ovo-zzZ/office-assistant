# 房源编码匹配：新表→原表映射方法

> 日期：2026-08-05 | 输出文件位于 SynologyDrive 非项目目录

## 背景

- **原表**（2046行）：园区置业资产录入模板，包含所有房源但G列"房源编码"为空，需从新表映射填充
- **新表**（1797行）：已通过编号引擎生成8位房源编码，但删除了约250条房源
- **目标**：将新表的房源编码按映射关系回填到原表G列

## 两表差异

| 差异 | 新表 | 原表 |
|------|------|------|
| 项目名称 | 合并简化（20个） | 细分拆开（38个） |
| 楼栋名 | `标准厂房1幢` | `1#` |
| 资产名 | 简写如 `南侧四层401` | 全称如 `龙州标准厂房1#南侧四层401` |
| 房源数 | 1797 | 2046（新表删了约250条） |

## 匹配策略（三遍级联）

### 第一遍：面积驱动匹配

按行逐条匹配，优先级从高到低：

1. **面积精确 + 简写嵌入全称（唯一）** → 高置信度 ✅
2. **面积 + 简写嵌入（多候选）** → 楼层消歧 → 方向消歧 → 楼栋号消歧
3. **面积 + 楼层（唯一）** → 验证方向一致性，方向不匹配则拒绝
4. **面积唯一** → 验证方向一致性，方向不匹配则拒绝
5. **面积 + 模糊简写匹配** → 楼层/方向辅助消歧

**关键消歧手段：**
- 方向提取：从资产名称中提取 `东/南/西/北`
- 楼栋号提取：`8#`→`8`，`A栋`→`A`，`标准厂房8幢`→`8`
- 方向不一致 → 标记为"需人工"而非强行匹配

### 第二遍：NaN面积文本匹配

针对空地/土地/杆线/基站/屋面等面积为空的特殊项：
- 项目名映射：原表细分项目 → 新表合并项目
- 类型分类：土地类/屋面类/整栋类
- 文本相似度评分（≥60分才接受）
- **每个新表条目最多匹配1次**（防止一编多）

### 第三遍：多候选消歧

面积多候选时，用楼栋号或数字号辅助消歧。

## 坑与修复

### 坑1：编码7位 vs 8位

新表中988条编码实际是7位（项目1-9缺少前导零），如 `1010401` 应为 `01010401`。

**修复**：写入时自动检测7位纯数字编码，补前导零。

### 坑2：Excel自动转数字

openpyxl写入 `"01010401"` 时，Excel将其当数字存储为 `1010401.0`，丢失前导零。

**修复**：写入前设置 `cell.number_format = '@'`（文本格式）。

### 坑3：面积相同不同房源误匹配

如8#南侧4层和8#北侧4层面积都是1611.24，简写不嵌入时按面积唯一匹配会出错。

**修复**：在"面积+楼层唯一"匹配后增加方向一致性验证，方向不匹配则拒绝。

## 复用时注意

1. 先确认新表和原表的列结构是否与本次一致（项目名称/楼栋/资产所在层/资产名称/面积/编码）
2. 如果也是"简写嵌入全称"的模式，直接用第一遍匹配即可达到90%+
3. 核心消歧逻辑：**方向 + 楼栋号**，这两者是最可靠的区分特征
4. NaN面积的特殊项需要单独的项目名映射表
5. 编码写入必须用 `number_format='@'` 防止Excel转数字
